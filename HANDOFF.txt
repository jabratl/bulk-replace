1. PROJECT SUMMARY
- Single-file web app (index.html, ~2030 lines, 104 KB, vanilla JS, no build, no deps except Google GSI script).
- Hosted on GitHub Pages. User works from Android phone mostly. UI text is English.
- Purpose: bulk-replace wrongly translated terms across 100+ Google Docs chapters per novel in Drive ("My Work" folder), via Drive API (drive.readonly) + Docs API (documents).
- Docs contain ONLY translated text (English or similar). Languages in scope: JP/KR/CN/RU raw + English translation. NO Bengali-specific work anywhere in this plan (existing Bengali-safe code from v4.x stays untouched, nothing new added). Raw (JP/KR/CN/RU) can only be used if the user keeps raw chapters as Docs (S13+).
- All user data is in localStorage via helper `store` (get/set). Never remove or rename existing keys.
- Rule of the project: SINGLE FILE index.html. No extra runtime files (so no PWA, no CDN libs, no network calls other than Google).
- NO AI. Everything is rule/dictionary based. (Optional AI suggestions and Google Sheets master are PARKED, see section 8.)

3d. ADDED IN v5.3 + v5.4 (S4+S5, built together)

- buildRe(p): when #smart is on and mode is lit/word, every " | " variant goes through smartPattern(term,opts); flags 'gu' (+i when Match case off); max SM_MAX_ALTS=40 variants per line (throws "Invalid pattern: ..."), terms over SM_MAX_LEN=60 chars match as plain text. Flexible-spaces switch is ignored while smart is on.
- Functions (before keepCase): smartOpts, smMaps (lazy: precomposed Latin map SM_PRE, halfwidth kana map SM_HALF), smCls, smartToken, smartPattern. Term is expanded, document text is never normalized (offsets stay valid). Separators (space - U+2010-2012 soft hyphen ' U+2018/2019 U+02BC ` U+00B4) in the term become [sep+zero-width]*; zero-width [U+200B-200D U+FEFF]* is allowed between all characters; ASCII -> fullwidth class; halfwidth/fullwidth katakana incl. voiced (ガ = ｶﾞ) and ー = ｰ; ё<->е; Latin base letter + any diacritic (precomposed or combining, \p{M}*); macron/circumflex vowel in the term also matches doubled forms: ā aa, ī ii, ū uu, ē ei/ee, ō ou/oo. NOT done on purpose: plain "ou/oo/uu" in a term does not match ō (too many false hits), and "Xiaoyan" in a term does not match "Xiao Yan" (list both forms as wrong variants; S9 clusters them).
- Entry flag rules.swap (editor checkbox #geSwap, saved in geSave, kept on edit): entriesToPairs adds the reversed order for each 2-word wrong form (Li Wei | Wei Li). Not in CSV/JSON import/export yet (rules{} is not exported).
- scan() result has .smart; buildReport "Matching:" line adds ", smart matching"; Replace all uses the match-by-match path when smart; lastRun/history runs store smart. Undo (prepare, history, from report) is refused for smart runs because the matched spelling can differ from the term.
